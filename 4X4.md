## 4. Recent Lessons Learned
**Capture insights to improve processes and avoid repeating mistakes.**

1. **Mu-plugin approach was fragile**: The standalone `debug-shipping-rates.php` required manual file placement and `debug.log` parsing. Integrating tracing into the main plugin with a UI toggle is more maintainable and user-friendly.
2. **File corruption from merge artifacts**: The main plugin file had a truncated function fragment and duplicate initialization block appended after the closing brace -- likely from a bad merge or copy-paste. Always verify `php -l` after merges.
3. **DRY violations compound over time**: Zone iteration logic, scope key methods, and line rendering were duplicated across 2-3 files. Each new feature copy-pastes from the nearest example rather than extracting a shared helper.
4. **Trait aliasing masks architecture debt**: 19 private scanner helpers are exposed as `public` via trait aliasing solely so self-tests can access them. This creates a false public API surface and makes refactoring harder.

## Bonus: Project Scope Outline

### 1. Goals
- Provide WooCommerce store managers a single admin page to audit all shipping/payment settings, scan custom code, and debug rate calculation issues.
- Replace ad-hoc debugging techniques (mu-plugins, `debug.log` tailing) with integrated, toggle-able tools.
- Maintain zero-configuration setup: install, activate, use.

### 2. Assumptions
- PHP-Parser is provided by the companion [KISS PHP-Parser Loader](https://github.com/kissplugins/wp-php-parser-loader) plugin. AST scanning degrades gracefully without it.
- Target stores have fewer than 100 shipping zones (preview is capped at 100 rows for performance).
- Contributors: primarily 1 lead developer (noelsaw1) with occasional contributions from Neochrome team (vishal).

### 3. Potential Risks
- **scanner-trait.php complexity**: At 1300+ lines with 8 responsibilities, this is the highest-risk file for regressions. Any scanner change can break self-tests, rendering, or condition formatting.
- **Self-test suite is paused**: No automated regression coverage since v2.7.14 (Sept 2025). New features like Live Rate Trace have no self-test coverage yet.
- **Stale branches**: 10+ unmerged branches may contain partial work that conflicts with current `main`.

### 4. Long-Term Maintainability
- **Priority refactor**: Split scanner-trait.php into focused classes (FileScanner, NodeDescriber, ConditionFormatter, StringExtractor).
- **Reduce trait aliasing**: Keep internal helpers private; expose only `scan_and_render_custom_rules()`, `create_parser()`, and `describe_node()` publicly.
- **Resume self-tests**: Add coverage for Live Rate Trace, then resume Phase 2.0 payment/mixed-logic tests.
- **Branch hygiene**: Delete merged and abandoned remote branches to reduce confusion.
